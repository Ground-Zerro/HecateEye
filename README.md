# 👁️‍🗨️ Око Гекаты

**L2TP traffic obfuscator**

Инструмент для обфускации трафика L2TP: на проводе — обфусцированный
UDP без узнаваемой сигнатуры протокола. Сам туннель (аутентификация,
маршрутизация, весь PPP) как и раньше устанавливают настоящие
`pppd`/`xl2tpd` — `hecate-eye` либо прозрачно проксирует их трафик
между собой (`mode=relay`), либо сам управляет `pppd` с обеих сторон
напрямую (`mode=ppp`).

## Возможности

- Два независимых режима: `relay` (рекомендуется — реальный PPP/L2TP
  остаётся видимым и управляемым штатными средствами) и `ppp`
  (pty-bridge — инструмент сам владеет `pppd`, для хостов без
  роутерного GUI/RCI).
- Роли `client` / `server` / `keenetic` — `keenetic` даёт агенту
  собственный сетевой адрес на роутерах Keenetic, чтобы штатный
  веб-интерфейс L2TP-клиента можно было настроить как обычно, без
  ручной правки конфигурации через консоль.
- Клиент опознаётся по идентификатору сессии внутри пакета, а не по
  адресу отправителя: смена порта на NAT или возврат трафика после
  простоя не выглядят для сервера новым пиром и не рвут туннель.
- Один бинарь для всех режимов и ролей; настройка — флагами командной
  строки или файлом конфигурации.
- Встроенная диагностика: счётчики отброшенных пакетов с разделением
  повреждения и потери, включая потери в очередях ядра, которых сам
  процесс обычно не видит.

## Установка

В `bin/` лежат готовые статические бинарники без внешних зависимостей —
`x86_64`, `mips`, `mipsel`, `aarch64`. Скачать нужный прямо на целевую
машину:

```sh
wget -O /opt/bin/hecate-eye \
  https://raw.githubusercontent.com/Ground-Zerro/HecateEye/main/bin/hecate-eye-mipsel
chmod +x /opt/bin/hecate-eye
```

Или скопировать из клона репозитория:

```sh
scp bin/hecate-eye-mipsel root@192.168.1.1:/opt/bin/hecate-eye
```

Для MIPS-роутеров берите `mipsel` (little-endian, подавляющее
большинство), `mips` — big-endian.

## Быстрый старт

```sh
# сервер (например, на VPS рядом с настоящим xl2tpd)
./hecate-eye --mode relay --role server \
  --listen 0.0.0.0:41850 --target 127.0.0.1:1701 \
  --key '<общий секрет>'

# клиент (например, на роутере)
./hecate-eye --mode relay --role client \
  --local 127.0.0.1:1701 --peer <ip-сервера>:41850 \
  --key '<общий секрет>' --session-id office-router
```

Затем в настройках штатного L2TP-клиента адрес сервера меняется с
реального на `127.0.0.1` — клиент подключается к `hecate-eye`, а тот
уже идёт наружу. Ключ должен точно совпадать на обеих сторонах;
`--session-id`, наоборот, у каждого клиента свой.

Полное описание режимов, ролей, всех флагов, диагностики и разбор типовых
проблем — в [USERGUIDE.md](USERGUIDE.md).

## Сборка из исходников

```sh
git clone https://github.com/Ground-Zerro/HecateEye.git
cd HecateEye

make              # под текущую архитектуру
./cross-build.sh  # все четыре целевые архитектуры в bin/
```

Кросс-сборка идёт через musl и даёт полностью статические бинарники.
Для MIPS используются именно **soft-float** тулчейны: userspace роутерных
прошивок (например, Entware) собран soft-float, а часть встраиваемых ядер
вообще не эмулирует инструкции FPU. При соборке MIPS обычным
`mipsel-linux-gnu-gcc` — получится hard-float бинарь, который на
роутере без FPU не заработает.

`cross-build.sh` ищет компиляторы в `PATH`, затем в каталогах из
`TOOLCHAIN_PATH`, затем в `toolchains/` рядом с собой. Чего не нашлось —
доставит сам: `musl-gcc` из пакетов дистрибутива, кросс-тулчейны готовыми
сборками с [musl.cc](https://musl.cc) (~100 МБ каждая). Свои пути скрипт
определяет сам, поэтому работает из любого места сразу после `git clone`.

```sh
TOOLCHAIN_PATH=/opt/toolchains ./cross-build.sh   # взять уже имеющиеся
NO_INSTALL=1 ./cross-build.sh                     # ничего не устанавливать
```
